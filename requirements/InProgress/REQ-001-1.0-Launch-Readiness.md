## Short Description

Takes AquaSuite from v0.14.0 to a sellable 1.0 for paying Blender users (Superhive/Gumroad, one-time purchase, free 1.x updates). It delivers: a per-setup version stamp that 1.x upgrades will rely on, with a notice on pre-release setups; plain-language error popups with a privacy-safe "Copy Report" for public bug reports; Beta labelling of the three liquid modes; correctly oriented rain streaks in all rain modes; an in-repo test suite that runs in every supported Blender with one command; Extensions-only packaging for Blender 4.2+; and the private-code / public-issues repo split with a release checklist as the final gate.

## Constraints

- **Particle rain streaks lie sideways today.** Rain and Reactive Rain use particle rotation mode `VEL`, which aligns the drop's **X** axis with velocity; the drop mesh is stretched along **Z**. Measured on 4.1 and 5.1: streak·velocity = 0.0.
- **`FunctionNodeAlignRotationToVector` does not exist in 4.1**; `FunctionNodeAlignEulerToVector` exists in 4.1 and 5.1. Neither has been checked on 4.2.
- **Blender 4.2 is not installed** on the development machine; only 4.1 and 5.1 are. 4.2 is the oldest promised version.
- **Update callbacks and frame handlers cannot open dialogs**, and a `bpy.app.timers` callback has no window in its context — a popup from a timer needs an explicit window override.
- **Headless (`-b`) Blender cannot show popups or use the panel.** Popups, clipboard UX and panel text are verified only by the Smoke Test.
- **RNA references to `scene.aqs_assemblies` items go stale after any item is removed** (they silently point at a different entry). Tests must hold uuid strings, never entry objects, across deletions.
- **`obj.matrix_world` and `obj.dimensions` are stale until the next depsgraph update.** Code computing from just-set transforms uses `matrix_basis`/base-mesh geometry (`rain_sim._world_matrix`, `still_water.object_dims`); tests call `view_layer.update()` before measuring.
- **`BUILD_TAG` has two jobs today**: the per-setup stamp (`AQS_AssemblyEntry.version`, set in `registry.add`) and the ocean wave-table tag (`ocean.build_ocean_tree` writes `nt[C.BUILD_PROP]`). `gerstner.py` documents the wave-table meaning.
- **A new `IntProperty` with default 0 reads as 0 on every existing file** — pre-1.0 setups need no write to be detected as data version 0.
- **The code repo's visibility is unknown** (`gh` is not installed); it must be checked, not assumed.

## Architectural decisions

- **Setup stamp**: every assembly entry stores an integer **data version** (0 = pre-release; 1 from 1.0; bumped only when a mode's saved layout changes) and the **add-on version** string that created it. The current `version` field is retired.
- **Compatibility**: from 1.0, no update changes or invalidates an existing setup; improvements to old setups are opt-in per assembly. Data version 0 setups get a "Made with a pre-release version" notice and a Rebuild action where the mode has one; no migration code for 0.x.
- **Version source**: `blender_manifest.toml` is the single source of the add-on version, read at runtime; `bl_info` is removed.
- **Wave-table tag**: the ocean node tree's tag gets its own constant, independent of the setup stamp.
- **Error pipeline**: every failure in an AquaSuite operator, property-update callback or frame handler goes through one recording path. Each distinct error shows **one popup per Blender session**: immediately for operators; deferred via `bpy.app.timers` otherwise; held during playback and renders and shown afterwards.
- **Bug report**: Blender version, add-on version, data version (when a setup is involved), OS, mode, plain message and traceback, with the user's home folder and the .blend path/name replaced by placeholders. Copied to the clipboard; the popup points to the public issues repo.
- **Beta modes**: Still Water, Water Hose and Rain Simulation are labelled Beta on their Create buttons and assembly headers, plus a one-time explanatory popup per mode.
- **Preferences**: a minimal `AddonPreferences` holding only the per-mode "Beta note seen" flags and a "Show Beta notes again" button.
- **Streaks**: every rain drop's long axis follows its current velocity (release velocity + gravity × age), in Rain, Reactive Rain and Rain Simulation.
- **Distribution**: Extensions zip only, `blender_version_min = "4.2.0"`; no 4.1 legacy package. `requirements/` and `tests/` never ship in the zip.
- **Tests**: `tests/` at the repo root; one runner command runs every test file in every Blender listed in a local, git-ignored config, prints PASS/FAIL per check and a summary, and exits non-zero on failure; `--bake` adds low-resolution bake tests. No third-party packages.
- **Repos**: code in the private `Blaxine/blender_aqua`; public `Blaxine/aquasuite` holds README, roadmap (no dates) and the issue tracker only, with no code and no zips. The manifest `website` and the bug-report popup point to `Blaxine/aquasuite`.

## UI / UX Notes

- **Assembly header**: Beta modes show a "Beta" tag after the mode label. A data-version-0 setup shows a single-line notice "Made with a pre-release version" in its box; Rain Simulation adds its existing Rebuild Emitter button there, other modes show "Recreate to update".
- **Create box**: the three liquid buttons carry "(Beta)" in their text.
- **One-time Beta popup**: shown after the first successful Create of each Beta mode on this Blender install: what Beta means (bakes required, slow at high resolution, RAM-heavy, coarse detail at Draft), a link to the public issues repo, and an OK button. Not shown again unless reset in Preferences.
- **Error popup**: title "AquaSuite couldn't …" + one plain sentence (no Python terms), a "Copy Report" button, and a line "Paste it in a new issue at github.com/Blaxine/aquasuite". After Copy Report, a status-bar confirmation "Report copied".
- **Empty/edge states**: if the clipboard write fails, the popup says so and the report goes to the console as a fallback. No popup ever appears during an F12 render or animation playback.

## Acceptance Criteria

- [ ] **AC1 — Stamp on create.** Every newly created setup records the current data version and the add-on version from the manifest.
- [ ] **AC2 — Pre-release notice.** Opening a file with setups made before 1.0 shows the pre-release notice on each of them (Rain Simulation with Rebuild); nothing in those setups changes until the user acts.
- [ ] **AC3 — One-command tests.** A single command runs the whole suite in every Blender listed in the local config and reports PASS/FAIL per check, a summary, and a non-zero exit on any failure.
- [ ] **AC4 — Bake tests.** With `--bake`, low-resolution bakes of Still Water, Water Hose (Normal) and Rain Simulation run and fail the suite if a bake produces no liquid.
- [ ] **AC5 — Operator error popup.** When any AquaSuite button action fails, a popup with a plain-language message and Copy Report appears; no message refers the user to the System Console.
- [ ] **AC6 — Deferred error popup.** A failure inside a slider/property change or the buoy frame handler produces the same popup shortly afterwards, at most once per distinct error per session, never during playback or rendering.
- [ ] **AC7 — Safe report.** The copied report contains the listed fields, and contains neither the user's home path nor the .blend path or file name.
- [ ] **AC8 — Beta labels.** Still Water, Water Hose and Rain Simulation are marked Beta on their Create buttons and assembly headers.
- [ ] **AC9 — One-time Beta note.** The Beta popup appears on the first create of each Beta mode per Blender install, not again after restart, and again after "Show Beta notes again".
- [ ] **AC10 — Streak orientation.** In Rain, Reactive Rain and Rain Simulation, each drop's long axis is parallel to its current velocity, including angled rain.
- [ ] **AC11 — Clean zip.** The built extension zip installs on 4.2+ and contains no `requirements/`, `tests/`, test config, git files or zips.
- [ ] **AC12 — Links.** The manifest website and every user-facing support link point to `github.com/Blaxine/aquasuite`.
- [ ] **AC13 — Repo split.** `Blaxine/blender_aqua` is private; `Blaxine/aquasuite` is public with README, undated roadmap and an issue template asking for the copied report.
- [ ] **AC14 — Release gate passed.** The full suite with `--bake` passes on Blender 4.2 and the latest 5.x, and every item of the release checklist is ticked on both.

## Technical Notes

**Stamp (Slice 1):**
- `core/registry.py` — `AQS_AssemblyEntry` (line 105) has `uuid`, `mode`, `created`, `version: StringProperty(default=C.BUILD_TAG)`; `add()` (line 196) sets `e.version = C.BUILD_TAG`.
- `level1/ocean.py:62` — `nt[C.BUILD_PROP] = C.BUILD_TAG` (wave-table tag; keep the behaviour, change the constant).
- Manifest parse at runtime: Blender 4.2+ ships Python 3.11, so `tomllib` is in the standard library. The manifest sits next to `__init__.py` in both the repo and the installed extension.
- Panel: `AQS_PT_water.draw` (ui/panel.py:305) builds each assembly box; `header.label(...)` at lines 341–343; per-mode drawing in `_draw_entry` (line 356). Rain Simulation's rebuild operator is `aquasuite.rain_sim_rebuild_emitter`.

**Errors (Slices 3–4):**
- Operator failure sites today: `core/delete.py` `guarded_create` (line 192; message cites the System Console at 209); `level2/rain_sim.py` create wrapper (620–625, System Console) and check tooltip (822); `level2/still_water.py` bake/free (`Bake failed`/`Free failed` at 454/485); `level1/rain_reactive.py` create (133) and ripple bake (167).
- Update callbacks: the `update=` functions in `core/registry.py` (`_resolution_update`, `_rain_params_update`, `_rain_domain_update`, `_rain_area_update`, `_hose_params_update`, `_hose_domain_update`) and `core/quality.py` `on_quality_update`.
- Frame handler: `core/handlers.py` `aqs_buoy_tick` (line 108) already catches per assembly and logs once via `_error_logged` (line 27).
- Clipboard: `bpy.context.window_manager.clipboard` (present in 4.1 and 5.1). Playback state: `context.screen.is_animation_playing`; render state: `bpy.app.is_job_running("RENDER")`.

**Beta / preferences (Slice 5):** Create buttons in `AQS_PT_water.draw` (ui/panel.py:326–329). `AddonPreferences.bl_idname` must equal the package's `__package__` (for an installed extension this is `bl_ext.<repo>.aquasuite`, not `aquasuite`); register the class through `__init__._all_classes`.

**Streaks (Slice 6):**
- `level1/rain.py` `make_droplet` (line 29) stretches `v.co.z *= 2.4` (line 36); `configure_rain_settings` sets `use_rotations = True`, `rotation_mode = "VEL"` (lines 64–65). Reactive Rain reuses both.
- `level2/rain_sim.py` `_drop_tree`: `GeometryNodeInstanceOnPoints` (line 272) → `GeometryNodeScaleInstances` with `(1, 1, 1.9)` (276–277) → `GeometryNodeRealizeInstances` (280). Per-point velocity is `(Vx, Vy, Vz − Gravity·dt)` with `dt` the age already computed in the tree. Use `FunctionNodeAlignEulerToVector` (present in 4.1 and 5.1) feeding the instance rotation.

**Tests (Slices 1–2):** prior art lives outside the repo (session scratch scripts: `verify_fixes.py` — 22 checks, `rs_impact.py` — Rain Sim bake + render, `zipload.py` — zip load). They import the add-on by inserting the parent folder into `sys.path` and importing the folder name; output lines start `SMOKE|`. Blender is invoked as `blender -b --factory-startup --python <file> -- <args>`. Extension build/validate: `blender --command extension validate <dir>` and `blender --command extension build --source-dir <dir> --output-dir <dir>`.

**Packaging (Slice 7):** `blender_manifest.toml` currently has no `[build]` table; `website = "https://github.com/Blaxine/blender_aqua"`; its header comment still describes 4.1 support. `.gitignore` already excludes `__pycache__/`, `*.zip`, `aquasuite_cache/`.

## Smoke Test

> Developer runs the app; the agent does not self-run.

1. Build the zip; in Blender 4.2 and the latest 5.x: Preferences → Get Extensions → Install from Disk. The add-on enables; the Water tab appears.
2. Open a .blend saved with v0.14.0 that has a Rain Sim: its box shows "Made with a pre-release version" and Rebuild; nothing else changed.
3. Create each mode once. The three liquid buttons and their headers show Beta; each Beta mode shows its note the first time only. Restart Blender: no note. Preferences → Show Beta notes again → the note returns.
4. Force an error (e.g. bake Still Water in an unsaved file): popup with a plain message and Copy Report; paste into a text editor — no home folder, no .blend path.

## Considered And Rejected

Nothing here is built. Each entry names the alternative, then why it lost.

- **Add-on version string as the only stamp.** Every release would need to know which versions changed which mode's layout; an integer that moves only on layout changes needs no lookup table.
- **One data version per mode.** Seven counters to keep consistent for a benefit (ocean changes not flagging rain setups) the opt-in Upgrade design already gives.
- **Stamping pre-1.0 setups as current.** A 0.13 Rain Sim would claim valid 1.0 data, defeating the stamp.
- **Migrating 0.13/0.14 setups.** Contradicts the promise starting at 1.0; only the author has such files.
- **Panel "last problem" box for errors.** Chosen against in favour of an immediate popup.
- **Status-bar message only for slider/handler failures.** Those failures would have no Copy Report.
- **Panel notice fallback for slider/handler failures.** A second mechanism to build and test next to the popup.
- **Unfiltered report.** Buyers post it publicly; user folder names and client .blend names leak.
- **Report without traceback.** Most reports would need a follow-up before anything could be fixed.
- **Beta labels only / a separate Beta section.** Labels alone leave Beta undefined for most users; a separate section changes a panel layout people already know.
- **Beta-note flag per .blend or per session.** Reappears in every new file / every launch.
- **Streaks along the release direction only.** Wrong on long, angled falls where gravity bends the path.
- **Streaks along velocity plus speed stretch.** Changes the look of existing scenes; motion blur gives the stretch where wanted.
- **`FunctionNodeAlignRotationToVector`.** Absent in 4.1; `AlignEulerToVector` exists in both tested versions.
- **pytest inside Blender.** Requires installing a package into each Blender's Python, against the zero-dependency rule.
- **Bakes on every run / never.** Every-run bakes make the suite slow enough to skip; never would have passed this release's empty-bake Rain Sim bug.
- **Keeping `bl_info` beside the manifest.** Two version strings that already had to be bumped in lockstep; 4.2+ ignores `bl_info`.
- **Public code repo / zips on GitHub releases.** Makes a free copy one click away from the paid product.
